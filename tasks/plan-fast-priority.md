# 红车优先通行修复（2026-10-08）

用户本轮反馈替代RC3的“只由红车择空”策略：红车出现后其他机制为它让路，尽快通过被占据车道。

## 行为契约

1. 一个红车拥有优先通行权，从接受出生开始到自然退出视野结束；不同时生成第二红车。抵近玩家阶段短暂停止新增交通；通过玩家并拉开安全距离后，只在不冲突的其他车道恢复普通车生成，仍不允许挤占红车路线。结束/重开必须解除通行权。
2. 普通NPC不再规划进入优先通道；通道前方普通车在可见、预警充分、周边安全时主动变道让行。正在转向的车仍连续完成，不能强制瞬移或取消成半车道状态。
3. 施工只暂缓新事件，已经可见的施工继续与地面同步推进；不为了红车擦除/冻结障碍。红车有路线时避开既有施工，没有空间时必须有限制动。
4. 路线选择以安全预计通过耗时为准，优先直通或主动让出的通道，避免红车与普通车互相抢同一空道。玩家逃生、车体间距、金币/补给安全约束不放宽，不能以“最短”理由绕过它们。
5. 金币和补给不是实体障碍，不删除已生成道具；新生成的引导路线和补给避开优先通道。红车经过后恢复原有难度规则。

## 实施与验收

- [ ] 当前逻辑有效初态下复现普通车不让行、红车期间继续出生/施工的缺陷。
- [ ] 独立优先通行控制器与交通/施工联动，小步红→绿。
- [ ] 道具生成协调，不修改已有拾取、燃油/损伤/评级算法。
- [ ] 有界通过、预警/倾斜、自然恢复、停止/超载/施工/双红车等专项及原有回归；独立代码审查。
- [ ] 新的唯一候选包与隔离试玩入口，保留RC2/RC3固定包及正式存档。

“最快安全路线”是有约束的局部路线规划，不宣称所有任意世界状态的数学全局最优。安全边界不是此轮可撤销的机制。
