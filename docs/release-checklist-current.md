## 每次新版本的交付检查

- [ ] 版本、目标提交、导出来源和实际改动清楚；不能把脏工作区构建冒称标签上的干净构建。
- [ ] 受影响测试与必要集成检查已完成，未执行/跳过项目明确记录；不借版本号声称通过。
- [ ] 在新目录准备玩家文件，拒绝夹带源图、测试、工具、私人存档、密钥或日志；保留引擎声明。
- [ ] 检查ZIP唯一成员、文件大小及SHA；实际解压后与源文件一致。
- [ ] EXE/PCK变化时取得对应新程序的隔离启动和相关行为证据；纯说明变化仅使相关文档/包证据失效，不机械重跑未变玩法。
- [ ] 下载页包含运行方法、操作、未签名提示、存档格式、兼容性范围和反馈入口。
- [ ] 更新独立SHA256SUMS与文件清单，保留旧包/旧回执，不静默替换已发布标签或附件。
- [ ] 发布得到明确授权；标签指向预期提交，上传后验证远端附件摘要，公开后检查匿名下载。

## 回退和问题处理

出现无法启动、存档损坏、持续崩溃等问题，先保存复现信息，不覆盖有效存档。停止使用问题版本，使用自己保留的成套旧EXE/PCK及与之匹配的旧存档副本；没有匹配旧档时不要强行降级。历史源码标签v0.2.0、v0.3.0不等于当前v7档兼容包。

维护侧先记录具体版本、附件哈希、操作和错误，再决定修复、发布新版本或撤回下载；不自动删除已发布证据、回退Git历史或改玩家存档。使用[问题反馈与已知限制](player/SUPPORT.md)收集必要信息，不要求玩家提交私人存档。

公开发布和开源许可是不同决定；仓库公开及Godot的MIT许可不为整个游戏自动指定开源许可证。保留现有素材来源记录，不因暂停签名而伪造许可或第三方采购缺口。
