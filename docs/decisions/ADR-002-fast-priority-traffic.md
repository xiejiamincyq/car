# ADR-002：红车采用协作式优先通行事件

## 状态与日期

已实施，候选验收中；2026-10-08。替代RC3仅靠红车自行找空道的策略，不替代既有交通安全与持久化规则。

## 背景

用户要求红车出现时其他机制主动让路，并尽快通过被占据的车道。原策略在同速双列普通车前形成永久陪跑：安全墙禁止红车同时挤入第三道，普通车却没有错列义务。单独放宽红车加速没有解决实际空间冲突。

## 决策

引入独立 `FastPriorityTraffic` 内部控制器，一个可见/待抵近红车拥有通行权。交通调度、普通车意图、瞬时速度目标、施工出生与新道具路线协同预留通道，依然使用原来的有限加减速、连续横移、充分可见预警、车体/安全墙/玩家逃生准入。

- 前方普通车安全打灯让行；齐头或密集队列通过暂时减速打开实际空隙，原巡航值不改。
- 错列优先选纵向后车。让前车向后越过伙伴会形成新墙和连锁制动，原红车停止距离不足，不能采用。
- 让行槽同时考虑目标道前后车辆和转向预约占据第三道的风险。红车不能抢占正在为前车腾出的同一个槽；有更快且安全的其他通道时仍可择道。
- 只延迟新增交通/施工及冲突的新道具路线。旧道具正常滚动/拾取；已发布施工按地面运动、受撞与正常离屏回收，不抹除。
- 红车抵近玩家时短暂停止新增交通，通过玩家并拉开安全距离后允许不冲突普通交通恢复；第二红车不抢当前通道。自然离屏、池世代变化或重开均解除优先权。
- 施工冷却按游戏时间计时，优先权延迟的是到期出生，不能因为红车反复出现而使整关施工饥饿。
- 红车通过后，普通出生不可因为只尝试一个受阻入口而一直丢机会。仅优先事件期间的普通车、或任何卡车，在原入口不安全时有限搜索其他入口；保留已抽巡航/转向方向及全部安全准入，无合法入口仍拒绝。
- 新施工出生先检查NPC该子步的有限运动包络，再进入实际车辆移动；只回滚尚未发布的提案，不能事后以删除已有施工修补重叠。

控制器不预加载交通宿主，避免循环脚本依赖；通过宿主内部安全查询和固定步长流程协调，不另造一套碰撞、道路移动或玩家资源算法。

## 否决方案

1. 删除/瞬移其他车、抹掉施工：破坏连续场景与因果，尤其会重现用户已反馈的路障消失观感。
2. 取消wall120或完整预警：以安全性换速度，出现无解横排或不可读的转向。
3. 永久暂停整关交通：困难模式变空；改为抵近阶段暂停、通过后的非冲突车道恢复。
4. 只让红车自行择道：双列同速车没有主动解堵行为，仍长期陪跑。
5. 始终刹停红车前车或让红车抢槽：红车被迫退出可见转向区域，可能向后离屏而没有超越；必须保护实际让行顺序与槽前后空间。

## 后果与边界

本轮保持既有评分、难度倍率、燃油/损伤、道具收益、玩家输入与正式存档不变。新模块纳入运行包白名单与源码指纹；旧RC2/RC3固定包不覆盖。

“最短”采用安全约束下的局部预计通过耗时，不是任意世界状态的数学全局最优。固定绝对巡航速度并不意味着红车在玩家所有超载速度下都一定更快；既有可见施工也不能被优先权魔法清除。专项、完整回归、独立交通矩阵、自然Main资源账本、实际包启动和真人体验分别验收，不能互相替代。
