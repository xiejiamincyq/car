# ADR-004：独立逐局生涯历史

状态：实施。日期：2026-10-13。依据：用户要求生涯记录每局分数、赛后自动保存且保留手动保存。承接ADR-003四独立档，不改变加载/复制/可恢复删除语义。

## 决策

SaveStore升级到v7，在原ConfigFile的history/runs中存储run_history。每次正常胜负结算追加一条，包含实际生涯局次、游戏得分、难度、赛道、车型、用时、距离、日期和完成状态。原top_scores仍是独立前五最高分，不用它充当完整历史。

生涯默认按时间倒序显示，每页5条，全部记录可翻页，不因显示分页截断存储。四档的历史随各档进度复制和删除，不能共享引用或混入别档。Main既有终态事件在记账后自动落盘，result_persisted防重复；写失败明确提示、保持内存，允许返回标题/暂停的手动保存重试，不能为了重试再结算一遍。

## 兼容与限制

v0–v6读取时生成空逐局历史，已有累计生涯、前五成绩、评级、解锁和设置保留；不知道的旧比赛不根据高分表补造。历史中的局次继续原career.runs而非重新编号为1。新档历史按顺序校验局次、类型、有限数值、赛道和车型；坏记录不被默认历史静默覆盖。

沿用原临时文件/校验备份/发布失败保护。旧候选不支持v7，回退必须先备份整个用户目录并明确使用对应旧快照，不能直接运行旧包覆盖新档。原用户档在开发自动测试中不升级；候选试玩前另作仅本机保留的恢复副本，私人档不进Git或玩家ZIP。

全部历史保存意味着文件随局数线性增长；本轮不设会悄悄删除旧局的任意上限。UI只创建一页控件，历史校验的赛道/车型目录在循环外构建；不将档案扫描塞入驾驶逐帧逻辑。未来若需分片存储必须另做带迁移与恢复测试的变更，不能以性能优化为名截断用户数据。

提前重开/退出而未产生胜负结算的比赛不伪造一个正常终局；这与原累计生涯定义一致。完整历史从升级后的真实结算开始，旧前五成绩只保留为最高成绩来源。
