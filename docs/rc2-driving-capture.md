# RC2：从实际驾驶开始的被动性能采集

2026-10-07。用途：落实本机成品计划R5性能门，不改变游戏、不自动驾驶，也不代替R6真人验收。网页监督已取消。

## 使用

由Codex先启动同一不可变RC2的正常EXE，创建当前活进程的`handoff.json`及独立APPDATA，再运行以下命令。`HandoffDirectory`必须换成本次真实交接目录，不能复用已结束的历史PID；工具不会启动、激活或关闭游戏。

```powershell
# PowerShell 7；项目根目录。本次目录名以实际交接记录为准。
./scripts/tests/observe_rc2_driving.ps1 -HandoffDirectory '<本次交接目录名>' -WaitSeconds 1800 -Seconds 1800
```

等待阶段最长1800秒；仅观察当前进程及其原生trace。检测到真实运行中的同一PID/会话、正式release、RUNNING界面、前台焦点、1920×1080、局号至少1且速度大于0后，才启动已有签名PresentMon 2.6.0及其1800秒计时。标题、倒计时、暂停、停车、结束、错误身份、旧记录、写入未完成及不可读文件均不触发。引擎慢启动时用trace创建时间对齐采样起点，不将初始化耗时误作数据过期。等待超时或游戏先结束，返回2并保留原因，不启动采集器、不重启游戏。

开局后仍需真实持续驾驶、施工/交通/超载和四关覆盖。门槛只控制采集开始，不保证之后每帧都属于驾驶；暂停、返回标题、停车和Dropped帧全部保留在原始输出，必须结合trace及真人过程说明重新分析。1800秒采集器存活不能直接证明30分钟驾驶，Present间隔也不自动代表实际屏幕帧率。

工具核对固定源`2a4d839`的RC2 EXE/PCK真实哈希、handoff哈希、进程路径/启动时间、隔离目录和采样开关，以及PresentMon签名/哈希。只在本次交接目录新建唯一observation子目录；不改正式存档、不跟踪输入、不联网、不提权。看门狗只终止它自己创建的采集进程，不终止游戏。

`-WaitOnly`仅检查触发条件，不启动PresentMon；其退出0也只表示触发条件成立。正常采集退出0只表示采集工具原生成功退出，不自动关闭任何成品门。
